The score combines four lenses: whether people and agents can find their way, whether each subject has one clear owner, whether current and historical work are visibly separated, and whether configuration and Git contain intentional material.

Learn the ten principles

Open any principle for the question it asks. These are repository outcomes, not required folder names.

P1 · Obvious entry point

Can a new person understand the repository, and can an agent reach governing sources and active work, without searching? A confident but wrong route is often more costly than a missing one.

P2 · Consistent naming

Can someone predict what neighboring items are called? The goal is consistency inside each ownership boundary, not one naming style forced across unrelated tools.

P3 · Smallest complete owner

Does each fact or artifact live in the smallest area that completely owns it? Repository-wide material belongs at the root; project-specific material belongs with that project.

P4 · Project-folder threshold

Has a body of work earned its own identity and lifecycle, or is it empty scaffolding? A project boundary should reflect a real outcome, not a preferred folder checklist.

P5 · One source of truth

Is each maintained fact or implementation authoritative in one place? Other locations should point to that owner or clearly say they are generated copies.

P6 · Lifecycle separation

Can a reader tell authored work from generated output, history, and disposable material? The audit follows the repository's own lifecycle vocabulary instead of prescribing a universal temporary folder.

P7 · Preserved history

Can important decisions and superseded work still be found without looking current? Git may be enough for a small project; higher-cost decisions may need an explicit record.

P8 · Visible abandonment

Does anything no longer maintained say so clearly? Age alone is not abandonment; stated lifecycle, content dates, and history carry more weight than modification times.

P9 · Configuration discipline

Are values that control behavior machine-readable, consistent, and free of exposed credentials? Prose may explain configuration, but automation should not have to scrape it for settings.

P10 · Git hygiene

Does version control hold authored decisions and intentional products instead of accidental machine output? Presence is not enough evidence; ignore rules and tracked-file state must be checked.

Now What: Proposed Changes

Proposed — not reviewed. This audit recommends changes; it does not approve or implement them.

Why the audit stops at a proposal

Evidence can show that a structure creates risk, but it cannot choose the owner's preferred names, canonical copy, or acceptable migration cost. Those choices become an implementation plan only after review.
